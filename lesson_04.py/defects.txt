1. Дефект №1: Ложноотрицательный результат метода contains() для символов на индексе 0.

Описание:
Метод contains() возвращает False, если искомый символ или подстрока находятся в самом начале проверяемой строки (на нулевом индексе).

Причина:
В блоке try-except используется ошибочное строгое неравенство `string.index(symbol) > -1`. Когда символ находится в начале строки, метод `.index()` возвращает значение `0`. Условие `0 > -1` в Python вычисляется как False, из-за чего переменная `res` не принимает значение True.

Проявление в тестах:
Падает параметризованный тест `test_contains_negative` при передаче аргументов `input_str="SkyPro"` и `symbol="S"`. Тест ожидает False (согласно поведению кода), но логически должен ожидать True, так как буква "S" присутствует в строке.

Рекомендация по исправлению:
Изменить строгое неравенство на нестрогое (`>= 0`) или использовать более лаконичный и безопасный встроенный оператор `in`:
return symbol in string

2. Дефект №2: Неэффективная реализация метода trim() при обработке ведущих пробелов.

Описание:
Метод trim() использует цикл `while` в связке с `string.startswith()` и `string.removeprefix()` для посимвольного удаления пробелов. Так как строки в Python являются неизменяемыми (immutable) объектами, на каждой итерации цикла в памяти создается новая копия строки. 

К чему это приводит:
1. Низкая производительность: Если на вход передать строку с большим количеством пробелов в начале (например, 1000 пробелов), цикл выполнится 1000 раз, создав в памяти 1000 промежуточных объектов строк, что приводит к избыточной нагрузке на процессор и сборщик мусора (Garbage Collector).
2. Избыточность кода: В языке Python уже существует встроенный, оптимизированный на уровне C-кода метод `.lstrip()`, который выполняет эту задачу за один проход без использования циклов.

Рекомендация по исправлению:
Заменить тело метода на более эффективное и лаконичное решение:
return string.lstrip()
